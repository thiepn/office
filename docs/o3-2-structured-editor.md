# O3.2 structured editor foundation
Tiptap 3.35.0 + ProseMirror + StarterKit + TableKit, bundled locally via esbuild; no CDN, no paid service. All 39 pre-existing tests retained. Browser command usage removed from application source. Native Markdown compatibility editor uses the same structured transaction engine with strict subset serialization. Conversion requires a user confirmation; existing documents are not migrated automatically.

Record schemaVersion 1 remains backward-compatible for Markdown records. Optional rich envelope version 1 stores originalMarkdown and canonical ProseMirror JSON. Original Markdown remains in body and immutable once converted. Revisions capture the prior rich envelope when present; CAS transaction boundary remains intact. Source view for converted records is read-only, exports explicitly distinguish original Markdown and structured JSON. Duplicate copies the full structured envelope. Search considers structured text. No downgrade or destructive normalization. Structured record validation rejects unknown node/mark/attributes, unsafe URI schemes and oversized data; schema checks also run in editor. Plain text paste, no arbitrary HTML ingestion, no drop handling.

Initial scope: headings, marks, list nesting, quotes, links, tables and structured undo/redo. Continuous paper surface, not actual page pagination. Structured JSON export is not DOCX export. No import/restore UI for structured JSON yet. A compatibility conversion only supports the O3.1 subset; advanced source stays unchanged. Original source view is not an editable Markdown projection. More extensive typography, formatting fidelity, accessibility and export remain later work.

Dependency qualification: the CI-generated integrity-pinned lockfile is committed; CI requires clean npm ci and a locally built bundle with no runtime CDN. No production deployment or Hub data migration.
