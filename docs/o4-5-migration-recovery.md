# O4.5 — staged migration and document backup contract
Base O4.4 PR #8 a8137b7938a7a1678064fda208f108e17489b2e8. Hub source baseline b90e5cb41992839dafab1b9744ba52143426c9ce, src/lib/office/documents.ts and device.ts. Hub storage scope is guest or user:<canonical account UUID>; the Hub schema lacks createdAt and trash. The export adapter accepts an already-selected OfficeDeviceStore, explicit scope confirmation and matching verified identity for account scope; never opens Hub DB or crosses origins. Hub repository not modified: a future approved Hub UI must call this adapter on the Hub origin and download its JSON. No direct migration from inaccessible origin.
## Portable contract
Envelope kind thiepn-office-portable-backup, version 1, source hub/office, scope, exportedAt, original records, per-document SHA-256, per-retained-revision SHA-256, envelope SHA-256. Hashes use UTF-8 JSON of recursively sorted object keys and preserved array order. This is a versioned JS canonicalization contract, not a signature or RFC 8785 claim. Raw Hub records retained in the backup; conversion preserves IDs, exact Markdown and revision history, sets trashed false and infers createdAt from earliest recorded revision timestamp. Source account must match destination; guest import requires typed guest attestation. A file is unsigned and can be regenerated by anyone; hashes detect corruption, not ownership authenticity. Verified target identity and live authorization are server authority. Hub exports are not read automatically.
Office backups preserve document snapshots, including structured content, layouts, trash and retained revision history. Browser validates actual editor grammar for current and historical structured content on import. Backup is not a full workspace image: unsaved drafts, mutation queues, local archives, account credentials are excluded and must be exported separately. No encryption. 1–100 records, 16 MB serialized UTF-8 limit; larger collections must be handled in separate batches, with no whole-collection atomicity claim.
## Import and recovery
Preview validates fingerprint and exact source scope, shows documents and local/cloud collisions. All collisions block entire batch, including identical IDs. Server rechecks under the same owner advisory lock as pushes, validates each document using existing server validator, checks 100-doc/64 MiB quota, creates only missing IDs, stores atomic idempotency receipt (including blocked results). Canonical JSONB server request hash is distinct from JS backup digest; sourceDigest is provenance metadata, not a signed server-verified source proof. Batch ID scoped to owner; mismatched replay rejected; current grants/session checked on every replay. Private receipt table, RLS/no direct grants, invoker public wrapper. No hosted SQL applied.
Durable owner-keyed migration journal is added to existing account IDB by additive version 4 upgrade. Stage before request; overlapping pending jobs and existing local IDs block. Retry uses exact batch and digest after reload. Local reconciliation and receipt state update in one IDB transaction; only missing or exactly matching clean snapshots accepted. If cloud committed but local record has diverged, retain pending job and do not overwrite; export recovery job for manual repair. No automatic rollback of cloud after commit. No destructive source deletion. Retention/quotas for local journal and full account lifecycle hooks remain production gates. No automatic Hub migration or production auth activation.
