## Implemented source
Separate account IndexedDB records keyed [owner,id]. Existing guest database and app UI unchanged. Durable immutable mutation queue appended atomically with local CAS save; retry uses same operation ID; concurrent acknowledgements cannot drop a different queue head; conflict retains both documents and halts upload. No automatic conflict merge or deletion. Explicit remote read adapter and guarded clean-cache acceptance; account-scoped workspace controller accepts only the shared verified session interface; unavailable or changed identity closes account workspace rather than leaking cached data. Offline edits remain durable and are accessible after verified reconnection. No offline identity trust on cold boot. This is a staged library, not an account-enabled product UI.
## Backend proposal and activation gates
Review private Office storage and authenticated RPC contract before any database migration. Server must derive owner from auth.uid(), assert expected owner, check non-anonymous identity, live session, Office-specific active client and connected grant, account deletion state. Recheck access on every read/write. No direct table grants, service role in browser, token telemetry, or client-controlled owner. Atomic server CAS and durable receipts must be tested on local PostgreSQL/Supabase with cross-account, revoked-client, deletion, replay and concurrent-write scenarios. No SQL applied, credentials configured, or live calls made. Account lifecycle export/deletion, storage quota and retention policy require explicit integration and review. Do not enable sync on a production origin yet.
